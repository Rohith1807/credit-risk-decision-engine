# Credit Risk Decision Engine — Model Card

## Model Purpose

Estimate probability of default for BNPL-style credit applications using behavioral transaction and application features.

## Selected Model

Unweighted LightGBM using raw predicted probabilities.

## Training Data

The model is trained on a synthetic historical credit portfolio with simulated applications, transactions, loans, repayments, and default outcomes.

Synthetic data is used because labeled real-world credit performance data is not available for this portfolio project.

## External Data Integration

Plaid Sandbox is integrated as an inference-time open-banking data source.

Plaid Sandbox observations are not used as labeled model-training data.

## Target

Default status based on 90+ days past due in the synthetic portfolio.

## Model Inputs

Representative feature families include:

- income behavior;
- account balance behavior;
- spending behavior;
- transaction velocity;
- BNPL payment burden;
- loan-to-income ratio;
- cash-buffer metrics;
- income stability;
- application characteristics.

## Model Selection

Logistic Regression, XGBoost, and LightGBM were evaluated.

Unweighted LightGBM was selected as the provisional production-style model based on its combination of ranking performance, Brier score, and portfolio-level probability behavior.

## Probability Calibration

Raw LightGBM probabilities were retained.

Sigmoid calibration slightly improved Brier score in the development sample but overpredicted portfolio-level default probability.

Isotonic calibration was rejected because the calibration sample contained too few defaults and produced unstable probability mappings.

## Policy Layer

The model does not directly approve or reject applicants.

Predicted probability of default is passed into an independently versioned policy engine.

Current simulated thresholds:

- Full Approval: PD below 4%;
- Low-and-Grow: PD from 4% to below 5%;
- Reject/Review: PD of 5% or above.

Open-banking fallback and data-confidence logic are handled separately.

## Explainability

Feature importance is reviewed for tree models.

Reason codes are generated by the policy layer rather than directly from model feature importance.

## Monitoring

The system supports monitoring of:

- approval rate;
- predicted PD distribution;
- observed default rate;
- Brier score;
- expected loss;
- expected profit;
- feature distribution drift;
- policy-tier distribution.

## Known Limitations

The training portfolio is synthetic.

The development dataset is relatively small.

Observed default counts in validation and calibration datasets are limited.

Plaid integration uses Sandbox data.

The system is a portfolio engineering and decision-science demonstration and is not intended for real consumer credit decisions.

## Governance

Model and policy versions are tracked separately.

Decision records include model version, policy version, reason code, predicted PD, approved exposure, and expected economics.
